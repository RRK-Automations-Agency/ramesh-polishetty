# Ramesh Polisetty — Fitness Coach Website

A fitness coaching website for [coachramesh.com](https://www.coachramesh.com) with a
photo gallery, an admin panel, and Supabase Auth / Database / Storage behind it.

## 🚀 Quick Start

1. **Open `index.html`** in your browser to view the site
2. **Setup Supabase** (required for the gallery + admin panel) — see [docs/QUICK_START.md](docs/QUICK_START.md)
3. **Access admin panel** — navigate to `admin.html` (or `/admin`)

## 🔧 Configuration

`config/config.json` is generated by `scripts/build-config.js` from environment
variables, so no credentials live in the repository:

```bash
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
BUCKET_NAME=photos
TABLE_NAME=photos
WHATSAPP_NUMBER=919963526973
PHONE_NUMBER=+91 9963526973
```

The generated file looks like this (`config/config.example.json` is the template):

```json
{
  "SUPABASE_URL": "https://your-project.supabase.co",
  "SUPABASE_ANON_KEY": "your-anon-key",
  "BUCKET_NAME": "photos",
  "TABLE_NAME": "photos",
  "WHATSAPP_NUMBER": "919963526973",
  "PHONE_NUMBER": "+91 9963526973"
}
```

## 🖼️ Photo Order

The admin panel controls the order photos appear in on the website. Every photo
has a numeric `display_order` (migration `20240101000004_add_display_order.sql`)
and the gallery pages read that column, then fall back to newest-first for rows
still on the default `0`.

From `/admin.html` the admin can:

- **drag a card** onto another to drop it at that position,
- tap **▲ ▼** on a card to nudge it one place,
- tap the **#number** badge to type an exact position,
- or use **Newest first / Oldest first** to reset the whole list.

The list is renumbered 1…N after every change, so the numbers never drift, and
the chosen order is what the matching gallery page shows.

## 🛡️ Security

- **The Supabase anon key is public by design.** It ships to the browser in
  `config/config.json`; the key itself grants nothing. What protects the data is
  Row Level Security — see the migrations in `supabase/migrations/`.
- **Admin writes are allowlisted.** Migration `20240101000003_secure_rls_admin_only.sql`
  adds the `public.admins` table and the `public.is_admin()` function. Photos and
  storage objects are publicly readable but only allowlisted accounts can insert,
  update or delete. Admin membership is *not* read from `user_metadata`, because
  users can write their own `raw_user_meta_data`.
- **Public signups should be disabled** in the Supabase dashboard
  (Authentication → Sign In / Providers → Email → "Allow new users to sign up").
- Admin panel requires a Supabase Auth login; only allowlisted accounts reach the panel
- Client-side rate limiting on login attempts (5 tries / 15 minute lockout)
- HTML escaping for anything rendered from the database
- Security headers (CSP, HSTS, nosniff, frame-ancestors, Permissions-Policy) in `vercel.json` / `.htaccess`
- `robots.txt` + `noindex` keep the admin panel and `/config/` out of search results
- `config/config.json` and `.env` are gitignored

## 🚀 Deployment

Vercel is the supported target ([DEPLOY_VERCEL.md](DEPLOY_VERCEL.md)):

1. Connect the GitHub repo
2. Build command: `node scripts/build-config.js`
3. Output directory: `.` (static site, no framework)

Environment variables (Supabase URL, anon key, bucket, table, WhatsApp + phone
number) must be set in the Vercel project; the build step writes them into
`config/config.json`.

### Custom / Apache server

1. Upload all files except `config/config.json`
2. Create `config/config.json` on the server with your credentials
3. `.htaccess` already sets the security headers and 404 page
